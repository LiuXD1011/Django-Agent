# 联网搜索真实页面验收计划

2026-10-12，Root 使用新增搜索 Provider 界面与最终核心执行小规模真实验收。先保持既有四模型、用户库、文件与密钥不变；只通过 Orca 新建有唯一名称的自有 SearXNG 验收服务。临时服务是实际 Node HTTP 服务，不替换应用后端，不伪造页面成功，也不代表公共搜索引擎质量。

本地服务提供真实 `/search?format=json&q=…`、两个可实际打开的 HTML 来源及明确 503 失败端点。来源包含本次实例的唯一标识与标准事实，避免回答凭通用知识就能命中；日志仅保存 query SHA、认证匹配布尔值、返回状态与请求序号，不输出真实密钥。仅在程序启动检查中标记 setupSmoke；页面与 Agent 请求保持 false。

Orca 按实际界面操作新建、编辑、留空保留合成密钥、设置默认、切换总开关、连接测试、失败提示、清除密钥的取消与确认、删除的取消与确认，并核对刷新后持久化。启用搜索后使用原对话模型发起最多一次小规模 Agent 回合，明确取消知识库选择；核对真实 web_search 轨迹、服务请求、标准答案和引用，并实际打开来源。模型新增用量上限 8 次，最长 10 分钟，不盲目重试。关闭总开关的零 HTTP 保证由真实数据库回归与页面保存读回分别证明，若没有实际关闭后的 Agent 请求，不计作该端到端场景通过。

条件允许时，在不含密钥的自有 DuckDuckGo 服务中点击真实公共搜索连接测试；挑战页、网络失败与空结果分别记录，不计作受控服务成功。已有 Google/Bing/Neo4j 等外部服务没有凭据时明确缺失，不编造厂商测试。

所有变更只针对本次自有服务和本次总开关/默认设置。先保存原设置的安全清单，结束时通过实际界面恢复原值、删除自有服务，检查没有活动任务及原四模型/凭据/业务资料摘要不变。保留会话和用量审计，正常停止精确所属的临时 HTTP 进程后冻结日志。当前仅为实施计划，没有宣称页面、厂商或安装版通过。

开始前已实际观察到 tenant2 原 `web_search_config` 为数据库 NULL，页面按既有核心语义显示启用。当前保存接口合并 JSON 对象，界面没有将对象还原 NULL 的操作，启用保存还要求选择默认服务。不得声称通过界面逐字恢复了原字段，也不为验收增添新的产品清空接口。Root 已授权本次隔离 QA 清理：页面先取消默认、关闭搜索并保存、删除仅本次自有服务，留完整安全快照；随后 Root 在无活动任务、无待确认 IPC、所有源目录写者正常退出的独占维护窗口，校验字段恰好等于本次已记录值后，仅条件更新 `tenant2.web_search_config` 回原 NULL。该步骤仅为清理，不计入 GUI 功能通过，不回滚其他字段或更新时间，不触碰模型、密钥、管理员密码。发现任何并发配置变化即拒绝恢复。实际维护尚未执行，后续须另记结果。
