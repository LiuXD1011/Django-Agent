# 浏览器验收数据的安装版离线副本计划

这是只读源码调查与执行设计，没有读取私有key/token/password/config值、复制数据、调用模型、操作进程或启动Windows程序。来源目录由既有[公开来源证据](../refactor-evidence/20261012-retrieval-chinese-query-live/live-after.json)确认是 `/home/liuxuedeng/.local/share/marlin-refactor/20261010-browser-qa`；该证据是历史时点，实际执行必须再取离线baseline。原安装DATA只有少量空业务数据，D02引用与H报告验收建议使用完整浏览器QA副本，而不修改 `验收数据 二次` 或保护25268的原数据。

优先复用正式[createBackup/restoreBackup](../../packages/core/src/storage/legacy.ts) 第283–316行。backup保存整份SQLite及所有非sqlite内部表的记录数/摘要，包含业务、Auth、任务/事件、FTS/vec及扩展shadow表；文件范围明确为 `media/.settings/.secrets/.cache/archives`。restore验证文件SHA/大小、数据库integrity/FK、owner关系、凭据可解密和全表摘要，在新的空目录内先stage后publish，失败不覆盖原目录。`desktop-profile/.logs/.document-work`不属于backup范围，不能称完整应用profile字节镜像。现有[migration回归](../../packages/core/test/migration.test.ts)覆盖backup/restore及破损备份拒绝；本次未重复运行。

注意正式[CLI backup](../../packages/core/src/tools/migrate.ts)会 `new CoreDatabase(source)`，而[构造器](../../packages/core/src/storage/database.ts)设置WAL并调用migration，不能把该命令当原QA只读导出。建议根代理先等所有付费/任务/认证intent终态，正常关闭来源owner，记录停后baseline；没有源owner、活动queued/running/pending job/actor、待确认IPC receipt或其他写者才继续。在独立Linux临时snapshot用 `openNativeDatabase(sourceDB,{readonly:true,fileMustExist:true}).backup(snapshotDB)` 与正式 `copyDataFiles(sourceRoot,snapshotRoot)`，原root只用readonly连接/读文件。只对snapshot构造CoreDatabase，再调用正式createBackup得到可验证manifest。隔离路径建议使用新的 `/home/liuxuedeng/.local/share/marlin-refactor/20261012-installed-clone-1/`，明确own marker，任何已有内容拒绝；原来源正常停止前后变化单独记录，不伪称正常checkpoint未改变物理DB SHA。

随后把manifest列出的文件复制到Windows独立owned中间目录，逐项SHA/大小和manifest身份保持；只搬数据，不搬Linuxnode_modules或native binding。目标建议固定 `C:\Users\lxd\AppData\Local\Temp\Marlin 安装验收 20261010\浏览器资料副本 20261012 第1轮`，与应用目录、原retained DATA、25268数据及旧failed WORK互不覆盖。正式restore用最新已核身份的installed bundled Node及其 `resources/runtime/core/dist/tools/migrate.js restore --source <owned backup> --target <new empty clone> --summary <owned summary>`；这是待绑定的命令模板，当前未执行。还需要Windows相同schema/checksum、FTS/vec扩展可加载的真实门禁，不以Linux成功代替。

跨平台路径先在离线snapshot检查，仅输出数量/hash/归属结果。原始文档 `file_path` 和图片 `storage_path` 等实际受控读引用必须是root内relative slash路径，文件存在且SHA匹配、storage_owned/parent/tenant不变。[workflow文件约束](../../packages/core/src/documents/workflow/files.ts)拒绝绝对路径、反斜杠/冒号、穿越及symlink；它依新的dataRoot解释relative引用，所以完整原media相对布局可保留。native restore不会像legacy import那样重写绝对路径：若实际受控引用含Linux绝对路径，不能把迁移步骤当无损clone或默改源，应记录条件并另审副本上的精确映射。历史trace/parser绝对诊断路径可留存，不作为Windows读取或删除权限。备份manifest还须预检Windows不能表示的路径段、case-insensitive碰撞，发现则拒绝并报告数量，不能静默改名。

[CredentialVault](../../packages/core/src/storage/credentials.ts)的AES-256-GCM使用同一个32byte `.secrets/credentials.key`，AAD是字段名，未绑定OS/机器/root。因此DB密文与原key须一起保留，跨平台仍由正式restore内部验证解密；不打印明文、不重新seal、不替换key，源/副本key与四个保护模型行的SHA分别核对。`.settings`与`.cache`按manifest保留；外部Neo4j/Langfuse/Web/MCP服务、代理地址等条件不会因数据clone自动变成Windows可用，不启动或重配它们来冒充验收。原browser服务恢复也应使用原数据和配置，由根代理安排，复制方案本身不恢复/终止任何服务。

认证必须走正常产品路径。[AuthService.login](../../packages/core/src/auth/index.ts)验证原password_hash并新建设备/refresh族；[AuthReader](../../packages/core/src/auth/reader.ts)每次重新核用户、membership与session。浏览器cookie/localStorage/Chromium profile不是IPC登录，不复制它们或把token注入renderer。[IPC adapter](../../packages/core/src/adapters/ipc.ts)只在DB `desktop_meta`有原本合法可解密的ipc.session时恢复，并对待确认receipt执行正式恢复；不能合成该记录。browserQA若无ipc.session，应看到登录页，再由根代理正常GUI登录来源账号、选择原个人空间。来源admin口令是否有已知QA凭据，本调查未读私有文件，无法证实；可由根已有私有QA记录或用户实际输入。如果没有，此项真实登录/D02/H有条件，不能私改admin哈希、注册新账号冒充旧个人空间owner，或利用浏览器token绕认证。

restore成功、尚未启动时要求全表摘要与manifest一致、媒体/key/model/source hash相同、FTS/vec exact seq保持；后续正常GUI login/refresh会合法改变device/refresh/desktop_meta及新profile/log文件，不能再要求全部文件/表完全相同。首次启动前还要求活动任务和pending auth receipts为零，避免clone自动恢复工作或重放未知付费请求。另准备只拥有新clone进程的review_only launcher，绑定实际installed payload和clone manifest，保留25268精确creation保护、无开发服务器、正常托盘退出，不改已经冻结的6926固定retained harness。
