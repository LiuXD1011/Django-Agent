## 导入流程设计

1. 只读打开旧库，检查 integrity、应用表结构和 migration版本；不得运行旧Django迁移，已知历史迁移有不可逆数据删除。
2. 检查旧库/媒体/解密材料是否完整，解密每个已存凭据并检查认证标签；缺失或错误时失败，不能创建替代key覆盖原key。
3. 生成源库/媒体hash与分表数量清单；在目标目录之外备份现有目标数据与解密材料。
4. 在新的临时目标数据库事务内导入31业务表及关联；完整保留UUID、bigint关联、JSON空值、软删除和空间权限。框架表不成为运行时依赖，索引由新核心重建。
5. 将媒体复制到目标受控目录并核对hash；重写存储根必须保留来源引用和页面/图片关联。
6. 核对FK、逐表记录数量和关键关系/字段/密文，确认通过后原子发布目标；失败删除仅本次临时产物并保留旧/目标备份。
7. 对运行中旧任务显式转换为interrupted或可安全恢复；未知结果的付费请求不自动重试。
8. 对源指纹记录导入history，重复导入拒绝重复写入或返回相同已完成结果；不得悄悄覆盖目标较新数据。
