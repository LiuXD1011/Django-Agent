# 个人知识库跨设备架构方案

> 日期：2026-10-02。状态：已实施第一批个人空间、网页设备认证与手机网页/PWA基础；完整 P0—P7 尚未验收。
> 实施事实与后续差距见[跨设备第一批实施报告](cross-device-evidence/README.md)。
> 产品定位：面向个人，每个账号拥有独立知识空间；支持同一用户跨设备使用，不以团队协作为前提。
> 部署定位：服务器保存权威数据并执行后台处理，网页、桌面与手机客户端访问同一服务；个人定位不等于纯本地部署。
> 本文定义后续主线。此前的[团队商用重构方案](重构方案.md)保留为历史审计与扩容参考，其中千人负载、团队协作和集群交付不是本轮自动继承的发布门槛；原有安全、任务一致性和检索问题仍须处理。

## 0. 一页结论

**推荐：云端权威、个人隔离、轻客户端、在线优先、渐进同步。**

用户安装 Windows、Linux、macOS 桌面客户端或 Android/iOS 手机客户端，也可直接打开响应式网页或安装 PWA，登录同一个账号即可访问自己的知识库、文档、会话和模型设置。手机端是正式产品入口，不只是缩小的桌面页面；先交付移动网页/PWA，再交付原生安装包。客户端不启动 Python、数据库、Neo4j 或 Docker；用户换电脑时不搬数据库文件。

首版优先交付两个层级：

1. **跨设备可用**：所有设备读写同一服务器，保存结果立即成为服务器事实；其他设备重新打开页面或条件刷新即可读到。
2. **跨设备及时更新**：变更游标、条件写入、删除标记和通知使已打开的另一设备及时更新。

完整离线编辑、双向文件夹同步、实时共同编辑不是上述能力的必要条件，留作独立增量。

| 决策 | 本方案选择 | 理由 |
|---|---|---|
| 产品边界 | 默认一个账号一个个人空间，空间内多个知识库 | 界面简单，数据归属明确 |
| 业务架构 | Django 模块化单体，同仓库不同进程角色 | 保留项目成果，不拆微服务 |
| 客户端 | Vue 响应式网页/PWA + Tauri 2 桌面与 Android/iOS 壳 | 同一业务界面与 API；移动交互单独适配，原生能力先验证 |
| 权威数据 | 全部已确认保存的业务数据在服务器 | 跨设备不依赖某台电脑在线 |
| 同步方式 | 先共享后端与条件刷新，再增量变更流 | 先解决真实需求，再优化带宽与体验 |
| 数据库 | 发布目标为单实例 PostgreSQL；SQLite 保留开发与受控试用 | 并发写、设备会话和后台任务更容易统一；不直接跳过检索迁移 |
| 检索 | 服务端 SearchAdapter；SQLite 旧适配器保留，PG 新适配器单独验收 | ORM 可用不代表检索可用 |
| 文件 | 首版服务器持久磁盘 + FileStore；按需迁移 S3 兼容存储 | 不因跨设备立即增设存储集群 |
| 图谱 | 保留 Neo4j，部署在服务端，作为可追踪投影 | 不删现有功能，不要求每个用户部署 |
| 通知与任务 | 数据库持久任务、轻量轮询；按实测再加 Redis | 通知丢失不能导致数据丢失 |
| 模型配置 | 默认用户自带 Key，按个人空间保存 | 不把个人 Key 当平台全局配置 |

**最小生产拓扑：一个服务端部署、一个关系数据库、一套文件存储、独立后台进程；无需 Kubernetes、分片、数据库集群或通用同步平台。**

## 1. 需求、假设与非目标

### 1.1 已确认需求

- 产品面向个人，个人数据默认不与其他用户共享。
- 同一用户在不同设备登录后，能使用同一份知识库与会话。
- Windows、Linux、macOS 安装包是产品方向；网页保持可用。
- 手机端纳入跨设备产品，支持 Android 与 iOS，复用同一账号、个人空间、知识库与会话。
- 不再依赖根 `.env` 与 `.env.example` 保存应用业务配置。
- 模型管理保留厂商预设、API Key 与必要高级选项。

### 1.2 本文采用的设计默认值，不冒充用户已确认要求

- 在线优先；断网时能保留未提交草稿，完整离线检索不列入首版。
- 默认一个个人空间；多个服务器、多个账号可以切换，但数据互不自动合并。
- 优先支持统一服务，也支持填写自托管 HTTPS 地址；两者遵循同一协议。
- BYOK（用户自带模型 Key）为默认；平台提供模型额度是可选产品能力。
- 回收站、同步保留期、设备数量与资源配额以本文建议值起步，发布前确认。
- 手机路线分两步：P1/P3 交付响应式网页与 PWA，P6B 交付 Android/iOS 原生包；后者是明确实施阶段，不以仅有网页作为手机安装包完成证据。
- Tauri 2 为手机壳首选；关键原生能力需通过锁定版本的双平台技术验证，不能从桌面插件可用推断手机可用。
- 手机首版不要求后台常驻、自动相册导入、完整离线 RAG 或推送必达；通知与系统分享接收作为后续增强。

### 1.3 本轮不增加

团队邀请与协作产品、同时编辑同一正文、CRDT、跨云数据库复制、客户端向量库、全量离线 RAG、自动监视整个硬盘、默认上传历史文件、订阅计费系统、集群 HA。

这不意味着删除已有成员或 API 功能。旧能力继续兼容，个人版新入口不引导用户进入团队流程；删除旧功能需另行确认。

## 2. 产品体验与核心页面

### 2.1 用户旅程

1. 用户在网页/PWA、桌面或手机端进入同一服务并登录，系统定位自己的个人空间；PWA 使用当前站点同源 API，原生端才通过受限地址选择器切换服务。
2. 用户创建“工作资料”“阅读笔记”等知识库，明确选中文件并点击上传。
3. 页面区分“上传中”“服务器已接收”“解析中”“可检索”“部分能力退化”，不把上传完成叫解析完成。
4. 用户关闭电脑后，服务器继续完成解析、向量与图谱任务。
5. 用户在另一台设备登录，看到同一文件、处理状态、会话和个人模型设置。
6. 用户在设备 A 发起回答，设备 B 可查看持久消息并订阅同一生成任务，而不是重新请求模型。
7. 用户在“账号 → 设备”撤销旧设备，其他设备保持登录，旧设备停止受保护访问。
8. 用户在手机上记录想法、选文件或拍照上传，电脑端看到同一云端结果；手机锁屏不取消已经提交的服务器任务，重新打开时恢复持久状态。

### 2.2 设置页分组

| 页面 | 对个人用户展示 | 仅运营管理员展示 |
|---|---|---|
| 账号 | 个人资料、密码、设备会话、个人数据导出/删除 | 账号停用与审计操作 |
| 知识库 | 分块、检索、索引状态、知识库模型选择 | 无全局运维入口 |
| 模型 | 厂商预设、模型、Key 是否已配置、思考策略、测试连接 | 平台模型政策与代理规则 |
| 个性化 | 默认知识库、语言、主题、提示词、跨设备偏好 | 应用品牌与默认政策 |
| 此设备 | 下载目录、缓存、网络状态、窗口、服务地址；手机增加蜂窝上传、权限与本机锁设置 | 无 |
| 系统 | 服务版本与可用能力的脱敏摘要 | 数据库、存储、Neo4j、Langfuse、部署启动项 |

“拥有自己的个人空间”不等于“拥有服务器管理员权限”。个人用户可以修改自己的模型 Key，不能更改数据库连接、全局代理或全局 Langfuse 凭据。

### 2.3 清楚表达保存状态

- “已保存到服务器”：服务器事务已提交，响应包含资源版本。
- “草稿仅保存在此设备”：尚未向服务器提交，其他设备看不到。
- “正在同步”：本机正在补拉已提交变更，不表示服务器数据丢失。
- “版本冲突”：保留本机内容，提示另一设备已有新版本，不能静默覆盖。
- “离线”：现有缓存可读；不声称全文检索、模型生成或远程文件均可用。

## 3. 总体架构与部署边界

```text
Windows / Linux / macOS       浏览器 / 手机 PWA        Android / iOS
      Tauri + Vue             响应式 Vue             Tauri + Vue
             \                    |                    /
                   HTTPS：认证、业务 API、SSE
                              |
                    TLS 反向代理 / 同源网页
                              |
                Django 模块化单体：API + async SSE
                   |                       |
              短事务业务服务          后台处理进程
                   |              ingest / chat / evaluation
                   +-----------+-----------+
                               |
                PostgreSQL：业务事实、任务、变更记录
                   |                  |               |
              FileStore         SearchAdapter     Neo4j 投影
            原文/图片/导出      pgvector + 全文     版本与删除保护
                               |
                         ModelGateway
                  按个人空间读取凭据、预算与策略
```

这是逻辑角色图，不表示每个框都需要独立机器。首版可部署在一台服务器，按进程隔离资源。单机故障会导致服务暂时不可用，备份用于恢复；不宣称高可用。

### 3.1 模块边界，避免为“优雅”创建空框架

- `accounts`：身份、个人空间归属、设备会话。
- `knowledge`：文档、版本、上传、删除与下载。
- `chat`：会话、持久生成任务、流式订阅与恢复。
- `models_config`：个人模型配置、凭据和能力；系统集成仍独立。
- `sync`（待新增的小模块）：个人空间变更记录、分页游标、设备确认点。
- `core` 或既有核心模块：窄接口 FileStore、SearchAdapter、ModelGateway。

服务方法仅在真实复用或事务边界需要时提取，不先为全部视图建立统一 Controller/Repository 基类。

### 3.2 服务器职责

认证授权、权威写入、解析与索引、模型调用、任务恢复、删除传播、备份、版本能力发布。

### 3.3 客户端职责

展示、文件选择与显式上传、条件读写、轻量缓存、断线恢复、设备登录和本机偏好。客户端不持有服务器数据库、存储、图谱的管理员凭据。

## 4. 数据存放矩阵

| 数据 | 权威位置 | 客户端保存 | 保留与删除原则 |
|---|---|---|---|
| 用户身份、密码摘要、设备会话 | 服务器数据库 | 登录状态与本机凭据 | 撤销会话立即阻止新请求 |
| 个人空间、知识库、标签、收藏 | 服务器数据库 | 最近访问元数据缓存 | 按资源版本更新，删除清缓存 |
| 已上传原文、图片、附件 | 服务器 FileStore | 明确下载或最近预览缓存 | 关联归属与内容哈希，绝不公共裸目录 |
| 文档解析、分块、摘要 | 数据库与版本化文件产物 | 必要分页内容 | 机器产物可重建，人工修改单独版本化 |
| 向量索引、全文索引 | 服务器搜索适配器 | 首版无完整本机副本 | 非权威投影，保留有效旧版本 |
| Wiki、图谱 | 业务事实/修订 + Neo4j 投影 | 展示缓存 | 人工编辑事实必须可恢复，不能仅存在图数据库 |
| 会话、消息、引用、个人记忆 | 服务器数据库 | 最近内容与本机草稿 | 完成态持久化后再通知设备 |
| 模型选择、个人提示词、检索配置 | 服务器个人空间 | 脱敏配置缓存 | 配置版本控制，避免旧设备覆盖 |
| API Key、解析服务凭据 | 服务端加密凭据存储 | 输入期间临时值，不持久存浏览器 | 只写入、返回 configured 状态 |
| 主题、语言、默认知识库 | 服务器个人偏好 | 本机应用缓存 | 可跨设备同步；按键或字段合并 |
| 窗口、下载路径、系统代理选择 | 设备本地 | 是 | 不上传用户绝对路径或本机代理密码 |
| 手机上传策略、本机锁、权限、临时采集文件 | 设备本地 | 私有目录与 OS 保护 | 不作为跨设备偏好；不默认备份登录凭据与私有缓存 |
| 手机通知订阅（可选） | 服务器设备会话关联 | OS/浏览器订阅标识 | 不作为登录凭据；退出/撤销后解绑，过期订阅清理 |
| 本地待上传文件与未提交草稿 | 设备本地 | 是 | 非云端已保存数据，明确标识 |
| 任务、版本、变更游标、删除标记 | 服务器数据库 | 各自确认游标 | 不依赖内存通知保证同步 |
| 诊断日志、模型用量 | 服务端最小化记录 | 可选脱敏诊断 | 不默认采集全文、密码、Key |

**跨设备同步的对象是业务资源，不是整个 `media/` 文件夹或 SQLite 文件。** 现有 `media/` 中的原文与图片应由迁移程序核对数据库归属后导入服务端存储；不直接把目录公开给所有账号。

客户端数据库、凭据和缓存按 `(service_id, user_id, space_id)` 分区。不同服务器即使账号名相同，也不得共享 token、草稿、缓存或游标。

## 5. 账号与个人空间：复用现有隔离，不推倒重建

### 5.1 产品模型

一个账号默认拥有一个个人空间，一个空间下有多个知识库。个人空间就是数据隔离边界，不是团队共享工作区。

当前模型已有 `User`、`Tenant`、`TenantMember`、知识库及资源租户字段，建议内部继续使用 `tenant_id` 作为隔离键，产品界面显示“我的空间”。不同时引入第二套 Workspace 表再双写。

### 5.2 待增加的明确归属

- 给 Tenant 增加空间类别与明确 `personal_owner`，仅个人空间约束一个活动用户拥有一个活动默认空间。
- 旧空间先标记为 legacy，保留原成员与权限；含多个真实成员的数据不能自动指定给某一个人。
- 个人新空间只允许 owner 默认访问；平台服务凭据和管理员访问使用独立入口与审计，不默认暴露成员分享界面。
- 新账号建用户、空间与 owner 成员记录在同一短事务完成；重试注册不能产生两个默认空间。
- 删除、停用用户与空间后，认证、任务提交、同步、检索、图片和导出一致拒绝访问。

### 5.3 查询纪律

客户端提供的空间选择只是提示。服务器从登录身份解析可访问空间，再查询资源；对象 UUID 不是授权依据。列表、搜索、task、sync、SSE、下载和模型配置全部纳入隔离测试。

后台任务必须持久记录空间与发起身份，不能从任意 JSON 或“第一个空间”推导归属。迁移现有 TaskRecord 时补显式范围，映射不明确的旧任务隔离审计，不猜测。

## 6. 设备登录、凭据与撤销

### 6.1 新增 DeviceSession，而不是仅记录一个 device_id

建议字段：会话 ID、user_id、服务端确认的客户端类型、用户可改设备名称、创建/最近访问时间、refresh family、凭据摘要、绝对过期、撤销时间与原因。

设备安装生成的 ID 仅用于体验关联，不是身份证明。两个浏览器会话可以显示为两个登录实例；不通过硬件指纹隐式追踪用户。

### 6.2 网页与原生客户端存储策略

| 客户端 | 首选方式 | 禁止作为默认方案 |
|---|---|---|
| 网页 / 手机 PWA | 同源服务端会话或 HttpOnly、Secure Cookie；修改接口保留 CSRF 验证 | 长期 refresh token 存 localStorage 或 Service Worker 缓存 |
| 桌面 | native auth adapter 持有 refresh，存 OS 凭据库；短期 access 仅在内存 | Key/refresh 存普通 JSON、IndexedDB 或同步偏好 |
| Android / iOS 原生 | refresh 仅交给受限原生层；iOS Keychain、Android Keystore 密钥保护的加密存储；access 仅在内存 | 明文 token 文件、通用 WebView 注入、系统云备份复制登录凭据 |

业务 API 复用，同一前端通过 AuthTransport 处理 cookie 或 Bearer 差异。浏览器/PWA 不回显 refresh；桌面和手机原生 refresh 接口由受限原生层调用，不提供任意 URL 的带凭据代理。

### 6.3 生命周期建议

- Access 建议 10 分钟；refresh 建议 30 天不活动过期、90 天绝对过期，发布前确认。
- 服务端保存高熵 token 的摘要，避免数据库泄漏后直接回放；设计摘要密钥轮换与老 token 兼容窗口。
- 每次 refresh 原子消费旧令牌并签发新令牌，保留家族关系以识别重放。
- 一个设备家族被确认重放后撤销该家族，不随意把所有正常设备踢下线。
- 同一设备客户端串行刷新；网页/PWA 多标签页协调刷新，桌面与手机原生层使用互斥；手机从后台恢复时也只允许一个刷新调用。
- 严格轮换下，响应丢失且客户端只剩旧 refresh 时，要求重新登录；首版不设计可反复使用旧 refresh 的宽松窗口。
- 改密/账号被盗处置可显式撤销所有设备；“退出此设备”只撤销当前会话。
- 每个受保护请求校验当前会话与用户状态；流订阅至少每 30 秒重新授权，设备撤销到流停止的数据窗口以该期限验收。

这些采用刷新轮换与重放检测原则，但现有自定义认证并不因此自动成为完整 OAuth 实现。[RFC 9700 刷新令牌保护](https://www.rfc-editor.org/rfc/rfc9700.html)

## 7. 同步策略：避免建立两套业务真相

### 7.1 第一级：在线跨设备使用，先交付

所有设备访问同一服务端。进入页面读取服务器数据；保存成功返回版本；另一个设备切回前台或重新进入页面时重新读取。针对正在处理的任务、打开的会话做条件刷新。

这已经满足跨设备使用，不依赖增量同步引擎。初期允许另一设备稍后刷新看到新状态，但必须清楚展示数据更新时间。

### 7.2 第二级：轻量增量同步

引入 SyncChange 作为**已提交业务变更的通知目录**。它不是新的业务数据库，也不拿它重建所有正文。事件只包含实体 ID、操作、版本和必要的低敏摘要；客户端按需读取资源。

- 活跃客户端建议每 10–30 秒补拉变更；切回前台、保存成功、网络恢复时立即补拉。手机仅在前台运行定时补拉，后台暂停，恢复前台重新授权后补齐，不用常驻轮询换取及时性。
- 当前打开资源以“另一设备保存后 5 秒内更新”为可选优化目标，使用更短的前台轮询；后台平台冻结时不承诺此时限。
- 变更较少时使用 ETag/304；无需首版同时引入 WebSocket 和 Redis。
- 后续可以增加单一通知通道，但通知仅提示 cursor changed。丢通知后补拉仍正确。

### 7.3 第三级：受限离线体验

按需缓存最近阅读内容；草稿仅本机保存。重新上线后拉取最新版本，再提交带 base_revision 的草稿。文档原文件上传、模型调用、服务器检索仍需要网络。

完整离线编辑与 RAG 是独立产品工单，涉及本机加密、数据授权过期、模型依赖和冲突合并，不借本轮偷偷增加。

## 8. 同步协议与一致性

### 8.1 待新增的数据结构

| 对象 | 关键字段与约束 |
|---|---|
| SpaceChangeHead | 每空间一行 last_seq，用于短事务内有序分配 |
| SyncChange | space_id、seq、entity_type/id、operation、resource_revision、created_at；unique(space_id, seq) |
| ResourceRevision | 首版直接给可编辑实体加递增 revision；大正文修订另存历史 |
| DeviceSyncState | device_session_id、space_id、acked_seq、last_seen；不决定业务授权 |
| IdempotencyRecord | space_id、actor、operation、key、request_hash、resource_id/结果；复合唯一 |

### 8.2 业务写与变更记录同事务提交

```text
验证身份/空间/动作
  -> 短事务锁 SpaceChangeHead（固定锁顺序）
  -> 校验资源 expected_revision，条件写入并递增 revision
  -> 分配 seq，写 SyncChange
  -> COMMIT
  -> 返回 resource_id、revision、cursor
```

首版按空间串行这些短写入，只锁 metadata 发布，模型、上传、OCR 和网络一律不在锁内。这牺牲很小的同空间写吞吐，换取跨设备顺序简单可靠；上线前用任务状态频率验证锁等待。

**不能仅用全局自增 ID 或 updated_at 做“已提交高水位”。** 不同事务可能按 ID 先后分配、反向提交，客户端越过尚未提交的较小 ID 会永久漏变更。SpaceChangeHead 在事务中先锁再分配，使同空间发布顺序与提交顺序一致；失败事务不留下可见变更。

### 8.3 拉取、分页与确认

示例为待新增接口，不是当前已部署协议：

```json
{
  "changes": [
    {"seq": 418, "entity_type": "knowledge", "entity_id": "doc-demo", "operation": "updated", "revision": 7},
    {"seq": 419, "entity_type": "session", "entity_id": "session-demo", "operation": "deleted", "revision": 4}
  ],
  "next_cursor": "opaque-cursor-demo",
  "has_more": false,
  "resync_required": false
}
```

- 游标是不透明、经校验的协议值，绑定 service、space、协议版本与保留 epoch；用户修改它不能读取其他空间。
- 开始一轮补拉时固定已提交上界 H，按 seq 分页至 H。中途新变更留到下一轮。
- next_cursor 只能越过本页已返回范围；不能直接设置成当时全库最大 seq。
- 客户端在本地事务中应用变更/标记资源失效和保存 cursor；崩溃后允许重复读取，版本比较使应用幂等。
- cursor 只说明客户端已收到通知目录，不说明每个正文都已缓存。缺正文的资源显式标记未加载。
- 重复 ACK 无副作用；恶意 ACK 不删除其他设备的可用变更。
- 建议变更与 tombstone 保留 90 天；过期游标返回 410 `sync_cursor_expired`，明确要求全量重建。

### 8.4 全量初始化与过期重建

服务端在一致性读点提供资源分页快照与水位 S，客户端完成快照后补拉 `seq > S`。

首版选择短生命周期的不可变元数据快照清单：在有界一致性读点同时捕获 S 与实体版本，保存 snapshot_id；各页从同一清单读取，不跨多个实时查询拼接快照。清单只含元数据，不复制原文件和向量；客户端后续读取正文时校验 revision，并补拉 S 之后的变更。清单绑定空间与会话授权、设置容量和期限，过期重新建立。若数据量超过生成预算，先明确返回限制并优化批处理，不维持跨用户翻页的长事务，也不把“分页查询当前表”冒充一致快照。

重建使用本机 staging 缓存，完成后替换当前缓存；保留未提交草稿。被删除实体不因旧草稿或缓存重新创建。不能让客户端清空服务器数据来“恢复同步”。

## 9. 多设备并发与冲突体验

| 操作 | 规则 | 用户体验 |
|---|---|---|
| 修改文档标题、笔记、提示词 | expected_revision 条件写；旧版本拒绝 | 对比本机/服务器，选择重载、复制为新笔记或重新提交 |
| 偏好字段 | 只提交变更字段，按字段版本或最新快照合并 | 改主题不覆盖另一设备改的语言 |
| 创建资源与上传完成 | 幂等键 + 请求指纹 | 重试不重复创建，内容改变不能复用原键 |
| 新消息 | client_message_id 唯一 + conversation revision | 网络重试返回原消息身份 |
| 同会话同时生成 | 首版每会话至多一个活动生成 | 第二设备显示“正在生成”，可订阅或显式取消 |
| 删除与旧编辑 | tombstone / 当前生命周期优先 | 旧设备显示已删除，不自动复活 |
| 文件正文更新 | 新 DocumentRevision，不原地覆盖旧文件 | 发布成功后新版本生效，处理中旧有效版本仍可读 |

采用 HTTP `If-Match` 的接口，版本不匹配返回 412；采用 body.expected_revision 的接口返回 409 `revision_conflict`。各接口固定一种写契约，不混用相同错误语义。

首版不做自动合并任意长正文或让“最后写入获胜”处理重要笔记。客户端保留用户输入；所有时间戳仅用于展示，冲突以服务端 revision 为准。

## 10. 上传、文件访问与删除

### 10.1 上传流程

1. 用户明确选择文件；客户端先检查基本大小与类型，服务器仍独立校验。
2. 建 UploadSession，绑定空间、知识库、幂等键、预计大小与过期时间。
3. 原文件传至 staging；首版有界单请求上传，分片/断点续传作为后续能力，界面不假报可续传。
4. 服务端计算 SHA256，校验实际大小、内容类型与配额，不能只信客户端哈希或扩展名。
5. FileStore 写入不可变正式对象并确保可读，再用短事务创建文档修订与持久任务。
6. 接收响应后用户可关闭客户端，后台继续处理。staging 或文件已写但 DB 失败时允许产生孤儿对象，由定期对账回收；绝不对外返回不可读的 ready 文件。

手机必须区分“本机尚未传完”与“服务器已接收”：锁屏可能中止前者，不影响后者的解析。上传响应丢失时先按 UploadSession/幂等身份查询，再决定重新选文件或重传；选中文件不等于服务器已收到。首版不承诺系统后台续传，详见 15.8。

推荐对象键：`spaces/<space-id>/documents/<document-id>/revisions/<revision-id>/<asset-id>`。显示名称单独存储，不直接用客户端文件名拼接服务器路径。去重首版仅在同一空间内进行，避免跨用户泄漏“他人是否上传过某文件”。

### 10.2 图片、预览与下载

所有资源先授权再返回。浏览器 `<img>` 不会自动带现有 Bearer 头，因此统一用 cookie 同源访问、鉴权 fetch 后 blob，或短时受限下载票据；不能把长期 access/refresh 放 URL。

首版优先鉴权代理读取文件，下载请求校验空间、资源版本与会话状态。若后续使用预签名 URL，限制单个对象、用途与短有效期，并明确已签发 URL 在过期前可能继续有效；严格撤销场景仍走授权代理。

禁止生产环境将整个 `media/` 映射成匿名可浏览目录。无论磁盘还是对象存储，客户端看到资源身份，不看到真实磁盘路径、桶管理员 Key 或其他用户文件。

### 10.3 删除与恢复

- 删除事务记录 tombstone、版本和待清理任务；随后立即从授权读取与检索候选中排除。
- 客户端收到删除变更后清除缓存与可续传状态；离线设备下次上线补拉或全量重建。
- 回收站建议保留 30 天，用户可提前彻底删除；保留期为可调整政策，不冒称现有实现。
- 物理清理覆盖原文、图片、分块、向量、图谱、生成预览、导出和缓存，按引用计数与版本规则执行。
- 删除期间旧 worker 不得发布新内容；清理失败持续可追踪，不能因索引迟到让已删除文件重新可见。
- 云端删除无法远程抹掉用户主动下载的文件；客户端也不能承诺清除已经被其他软件复制的数据。

## 11. 后台任务与版本发布

### 11.1 保留持久任务，补齐身份与版本

现有 TaskRecord、领取/心跳/恢复、取消和短事务发布保护可以复用；当前并未形成完整 revision/fence/staging/outbox 协议，详见[最新收尾报告](refactor-evidence/CLOSEOUT.md)。

待补字段：space_id、actor_id、resource_id、expected_revision、单调 fence、attempt、lease、idempotency_key、取消与预算。

### 11.2 文档生命周期

```text
uploaded -> processing -> staging_ready -> published
                  |               |
                  +-> failed      +-> cancelled / superseded
```

上传修订与 active_revision 分开。对初次上传，未发布前页面明确“待处理”；对更新文件，发布前保留上个可用版本。新的 chunk、图片、索引与图谱绑定 revision，不用“删除旧产物再慢慢补新”的方式重建。

### 11.3 发布条件

短事务同时检查：资源仍存在且未删除、expected_revision 一致、task owner/fence/lease 有效、未取消、产物完整。成功后切换有效版本、更新任务结果、记录 SyncChange；图谱等外部投影通过同事务的待投影记录派发。

外部系统不能与数据库假装拥有一个大事务。派发至少一次，消费者按空间/资源/版本去重并拒绝旧版本；通知失败可重放，旧 worker 至多写出可回收 staging，不能改变当前 active 指针。

### 11.4 资源隔离

解析、聊天与评估分别有并发预算，初期同机不同进程即可。每用户限制上传字节、文档解析并发、活动生成数、请求频率和模型预算，避免一个个人账号耗尽全服务。

运行任务使用数据库事实，不把 LocMemCache 或进程内字典作为跨进程任务终态。Redis、Celery、Kafka 不列为前置依赖；当吞吐/延迟证明需要时再替换调度适配器。

## 12. 会话与跨设备流式回答

### 12.1 请求、生成、订阅分开

- 创建消息请求先持久化用户消息、助手占位、生成任务与请求幂等身份，返回 message_id / generation_id。
- 服务端生成不跟某个桌面窗口或手机页面绑定。关闭窗口、锁屏或应用被系统回收仅断开订阅，不默认取消已确认提交的生成。
- 设备 B 按持久消息身份读取状态或订阅同一 generation，不重复调用模型。
- 同一设备请求重发返回原 generation；主动重新生成使用新操作身份并提示可能产生新费用。

### 12.2 SSE 与持久状态

复用现有 StreamState / StreamEventRecord 与 continue-stream 的兼容入口，逐步迁入明确协议。每个 generation 使用单调 seq，事件携带 message_id、generation_id 与状态。

建议按时间/字节批量持久化增量，完成事件必须在最终 Message、用量、引用与状态提交之后发送。断线补拉或游标过期时返回最终快照；首版不承诺强杀时保留最后一个尚未落库 token。

SSE 事件流与空间 SyncChange 是两种不同粒度：前者传生成片段，后者通知“某消息/任务版本已更新”，不把每个 token 写进全空间变更目录。

### 12.3 网络、取消与付费边界

- 自动重连只重新订阅，不重建任务、不自动重试已开始付费的模型请求。
- 用户显式取消产生耐久取消状态，各设备统一停止；晚到结果不能覆盖取消终态。
- worker 崩溃且无法确认供应商已执行的请求，标 interrupted 并由用户显式重试；没有供应商幂等能力时不承诺“付费恰好一次”。
- 终态引用对应已发布文档版本；过期或已删除引用明确标识，不能越权读取旧原文。
- 每次补拉重新授权，长连接定期检查会话撤销；access 不出现在订阅 URL 中。

### 12.4 ASGI 迁移要求

当前仅有 ASGI 入口，并未完成真正异步 SSE。后续需要 async iterator、有界通知等待和阻塞工作隔离，同时审查中间件与数据库连接策略；不是替换启动命令即可完成。

Django 5.2 的事务逻辑仍应封装为同步短函数，再从异步边界调用；流等待不持有事务或数据库连接。[Django 异步支持](https://docs.djangoproject.com/en/5.2/topics/async/)、[StreamingHttpResponse](https://docs.djangoproject.com/en/5.2/ref/request-response/#django.http.StreamingHttpResponse)

现有 worker 命令只支持 documents、evaluation、default 队列；chat 队列与生成入口是本方案待实现内容，不能直接把 `--queue chat` 当作现有命令执行。

## 13. 检索、模型与个人凭据

### 13.1 模型配置跨设备，密钥不跨设备回显

继续复用 ModelConfig 的空间归属和 CredentialJSONField。所有模型配置增加 revision；返回厂商、端点、模型、能力和 key_configured，不返回原始 Key。

用户保存 Key 时经 HTTPS 一次写入，客户端随即清理输入值；空值表示“不改变”还是“删除”必须采用明确接口，不通过模糊空字符串清空凭据。日志、同步事件、导出与截图提示不暴露 Key。

平台默认模型如需提供，使用平台 credential reference 与明确 policy；不要把一个平台 Key 复制到所有个人空间。默认 BYOK 不隐式引入计费系统。

### 13.2 统一 ModelGateway

对话、摘要、标题、查询改写、Embedding、Rerank、VLM 与图谱提取均在服务器按空间选择配置与预算。一次轮次冻结策略快照；另一设备修改设置只影响后续调用。

预算在数据库中条件领取，绑定空间、任务、尝试与预算周期；并发进程不能分别用内存计数超额放行。调用前预留、结束按实际用量结算，超时且供应商执行状态不明时标待核对，不立即当作零费用释放。并发槽有租约与恢复规则；首版统一经 ModelGateway 落地，不额外建设通用计费系统。

用户输入模型地址是服务器出网目标：校验协议、DNS/重定向和私网地址；自托管私网模型通过运营管理员批准的连接配置使用，不能让普通个人账号访问服务器元数据或内部管理接口。

### 13.3 EmbeddingSpace 与索引版本

空间标识至少包含 provider/endpoint 非敏感指纹、精确模型/修订、维度、归一化/距离和预处理版本。不以“维度相同”认定模型等价，也不将密钥明文混入索引标识。

更换 Embedding 模型时构建新 IndexGeneration；校验完整性后激活，失败保持旧索引并在页面说明。查询只在有效空间内排序；多模型空间融合在结果层进行，禁止直接比较不同语义空间距离。

### 13.4 PostgreSQL 检索是明确阻断项

当前 `DATABASE_URL` 可切换 ORM，但 search.py 在非 SQLite 后端明确返回 unsupported。因此：

1. 先实现并验证 PG SearchAdapter，再迁移生产检索；不能仅改数据库地址。
2. 初期按授权后候选精确检索建立真值集，验证个人空间和知识库过滤、禁用/删除与混合模型。
3. ANN 只在实测需要时启用；过滤可能降低返回数量，需要执行计划、扫描预算和真值对比。[pgvector 官方过滤与扫描说明](https://github.com/pgvector/pgvector)
4. 中文全文不直接使用未经验证的默认英文词法；对术语、编号、中英混合建立固定 oracle，再选应用分词 + PG 全文或其他经测试方案。
5. 排序、候选预算与重排复用生产/评测内核，迁移前后分别报告召回质量与耗时。

保留 Neo4j 现有图谱能力。机器提取图为投影；人工图编辑先写修订事实，再投影。Neo4j 故障如何降级由产品能力说明决定，不把图功能失效伪装成完整健康，也不必让所有普通文档列表不可用。

| 范围 | 示例 | 谁能改 | 存储 |

| 部署启动 | 数据库地址、数据根、Hosts、CORS、线程预算 | 部署管理员 | 启动配置与进程环境/secret 注入 |

保留已完成的去根 `.env` 方案。应用业务配置不重新塞回环境文件；Compose 或平台 secret 管理属于服务部署，不等同用户模型配置。

浏览器不会获得数据库密码、服务器加密主密钥、全局 Neo4j 密码或服务器文件路径。设备配置不允许以“同步设置”为名覆盖服务器全局参数。

## 15. 客户端实现：一份 Vue，网页/PWA、桌面与手机壳

### 15.1 三个窄适配点

- **EndpointResolver**：统一业务 API、refresh、SSE、图片、下载、上传地址。
- **AuthTransport**：网页/PWA cookie/CSRF 与桌面、手机 native Bearer 的差异。
- **DeviceStore**：缓存、草稿、同步游标与设备偏好；按服务/账号/空间分区，手机实现加入有界私有缓存与本机锁策略。

Vue 页面只调用既有业务 API 封装，不各自读取 token 或拼接服务器地址。不要引入通用插件框架；这三个边界直接解决当前不同请求路径的问题。

### 15.2 服务地址与能力协商

- 正式环境 HTTPS；本机 HTTP 仅允许显式开发配置，不用于把真实用户 token 发送到任意明文地址。
- 首次读取 public capabilities，包含 service_id、API 兼容范围、客户端最低版本、功能开关、上传限制；不含账户数据和密钥。
- service_id 变化或地址切换时清除活动登录状态，选择相应独立缓存；不要把旧服务器 refresh 自动发给新服务器。
- 公共能力接口不接受带用户凭据的跨主机重定向；业务请求默认限制目标来源，外链使用系统浏览器。
- 缺失 API 能力明确提示版本不兼容，不循环尝试未知路由。

### 15.3 平台差异

- 浏览器：首选应用与 API 同源；个人缓存默认关闭完整原文离线，退出时清除账号相关本地状态。
- Tauri：只打包本地可信前端；远端文档、模型返回 Markdown 不获得 native 权限。
- 下载/选文件使用最小原生能力；文件选择是用户意图，不允许前端任意扫描磁盘。
- 登录、上传和 SSE 在 Windows WebView、macOS/Linux WebKit、Android WebView、iOS WKWebView 与手机浏览器都做实机测试；PWA、原生壳的会话与存储分别验收，不用桌面 Chromium 结果替代。
- 用户登出清除受保护缓存与 token；未上传草稿可显式选择保留在同账号分区或导出，不能切换账号后显示给新用户。

### 15.4 手机端产品定位与技术路线

**手机负责随时阅读、提问与轻量采集；电脑负责长文整理；服务器负责共同的数据与重处理。** 手机不维护独立知识库副本，不运行 Python、向量库或图数据库，也不另建 mobile API。

| 层级 | 交付物 | 用户价值 | 明确边界 |
|---|---|---|---|
| M1：移动网页 | Android Chrome / iOS Safari 的响应式 Vue | 直接登录、阅读、搜索、问答、笔记与显式上传 | 不要求安装，不承诺后台上传 |
| M2：PWA | manifest、图标、可安装应用壳、受控静态缓存 | 主屏幕入口、独立窗口、保留本机草稿 | 安装和权限以能力检测/实机为准；不是完整离线知识库 |
| M3：原生手机包 | Tauri 2 + 同一 Vue + 必要 Kotlin/Swift 插件 | 私有凭据存储、系统选文件/拍照、应用生命周期集成 | Android/iOS 分别验证，插件能力不从桌面继承 |

M1/M2 是同一前端发布的移动形态，M3 是同一业务前端的手机封装，不复制三套业务逻辑。原生技术选型先按 15.10 做小型验证；未通过的能力保留待办和失败证据，再单独评审最小原生实现，不偷偷引入另一套前端框架。[Tauri 手机开发前置条件](https://v2.tauri.app/start/prerequisites/#configure-for-mobile-targets)

### 15.5 手机端页面与交互

底部主导航建议四项：“知识库 / 问答 / 收集 / 我的”。小屏单栏，大屏恢复分栏；使用同一资源路由和 Pinia 业务状态，布局不另建一套权限或数据模型。

- **知识库**：最近阅读、收藏、知识库列表与搜索；文档详情以阅读为主，编辑长文按段进入，不把桌面图谱面板强塞进小屏。图谱保留简化关系列表及可展开视图。
- **问答**：当前会话、历史消息、来源卡片；点引用打开授权文档与对应版本，返回后保留输入。流式滚动只在用户位于底部时跟随，用户阅读旧消息时不强行跳底。
- **收集**：新建笔记、选文件、拍照/选图；先选目标知识库，再展示内容和上传确认。笔记首次保存到服务器后才能标“跨设备可见”。
- **我的**：模型配置、账号、设备、同步状态、缓存与本机权限；高级运维不进入手机个人入口。手机也能设置个人模型，只显示 Key 配置状态，不下载已有 Key。
- 触控目标建议至少 44 CSS px；键盘弹出、刘海/底部安全区、横竖屏与动态视口需适配；正文和表格不导致整个页面横向溢出。
- 输入法组合期间不提交；回车换行，显式发送按钮发送；上传与生成有明确停止/取消入口。加载、空态、无权限、断网、服务器处理与冲突各自呈现。
- 初始验收宽度覆盖 360/390/430 CSS px，平板按自适应布局另测；最小系统/浏览器版本仍需发布前确认。

### 15.6 手机端认证与本机数据

手机原生层复用 DeviceSession、刷新家族与服务端撤销策略。网页登录/PWA 和原生安装是不同登录实例，不能复制网页 cookie 假装同一凭据；设备页面显示可改名称及客户端形态，不依赖硬件指纹。

- **iOS Keychain**：refresh 使用设备绑定、非同步的条目访问策略；解锁后可用策略根据实际前台需求选择，默认不经 iCloud 同步。账号切换/退出主动删除相应凭据，卸载重装后若残留条目可读也不得自动登录，需要显式重新确认和服务端校验。[Apple Keychain](https://developer.apple.com/documentation/security/keychain-services)
- **Android Keystore**：Keystore 保存加密密钥，refresh 密文放应用私有存储；不要把 Keystore 描述成任意字符串保险箱。密钥、认证文件与私有缓存从备份/恢复迁移策略排除；密钥丢失或失效走重新登录，不降级明文。硬件保护是否可用按设备检测，不宣称全部设备均硬件隔离。[Android Keystore](https://developer.android.com/privacy-and-security/keystore)
- access 在受控内存中使用，refresh 不返回 Vue 页面；原生 HTTP 能力只允许当前服务及确认的业务路径，日志不记录 Authorization。模型 Key 只在本次用户输入时临时存在，经 HTTPS 写入服务器后清空。
- “本机锁”可选 PIN/生物识别，只控制本机展示/凭据解锁，不替代服务器认证、改密再认证或设备撤销；授权失效时仍须登录。进入后台隐藏敏感预览，禁止在诊断日志/通知中复制正文。
- 原生正文/草稿缓存采用可验证的加密存储或先关闭持久正文缓存；密钥受 OS 存储保护。按服务/账号/空间分区，设容量与过期时间，空间不足时先淘汰可重建缓存，保留草稿并提示存储失败。
- PWA 的 IndexedDB 仅提供同源隔离，不宣称等同硬件安全存储；默认不持久缓存原文，可保留明确标识的草稿，用户可清理。系统回收浏览器存储可能丢失未上传草稿，不能承诺本机草稿永久耐久。
- 退出/撤销后不再获取云端数据；离线手机收到撤销前可能仍有旧缓存，因此首版不宣称远程即时擦除。手机丢失时用户通过另一设备撤销登录；云端权威数据不因手机丢失消失。

### 15.7 手机生命周期、弱网与恢复

客户端订阅状态和业务任务状态必须分开。手机生命周期使用同一前台恢复协调器，按以下顺序串行处理：

```text
进入后台 / 锁屏：保存草稿 -> 暂停轮询与前台订阅 -> 不取消已提交任务
恢复前台：本机解锁（若启用） -> 验证/单飞刷新设备会话
         -> 核对服务身份和 recovery_epoch -> 补拉变更或重建缓存
         -> 读取正在看的消息/任务快照 -> 订阅同一 generation 的新事件
网络切换：连接失败 -> 有界退避与抖动 -> 重新授权/补拉 -> 恢复原订阅
```

- 应用恢复事件、网络恢复事件、路由进入事件合并，避免三次 bootstrap、refresh 或 SSE；每设备每会话最多一个有效订阅，旧订阅用 generation/连接世代丢弃。
- Wi-Fi/蜂窝切换不改变上传或消息幂等身份；请求响应不明时查询已提交状态，不重新发起付费生成。服务器仍生成时显示原任务；仅用户明确“重新生成”才能创建新任务。
- 本机草稿持有 base_revision，恢复后先取得服务器版本；电脑已改过时进入冲突流程，不用手机时间戳覆盖。服务器已删除时仅允许把草稿显式另存为新资源。
- 后台不依靠 JS 定时器或 SSE 保活，不持续耗电补拉；“5 秒内更新”只评估前台活跃窗口。后台调度是 OS 条件驱动，不能作为跨设备事实传播保证。[Android 后台任务边界](https://developer.android.com/develop/background-work/background-tasks/persistent)
- 系统杀进程后，重启以持久 generation_id / upload_id 和服务器快照恢复；token 失效先登录。低内存时限制大 PDF/长列表渲染，分页/虚拟列表不一次载入全部原文。

### 15.8 手机文件采集与上传

首版实现“选文件 / 选图片 / 用户主动拍照”，OCR、分块、Embedding、图谱仍由服务器处理。权限在点击功能后才请求，拒绝或撤销权限不阻止阅读和问答；不申请全盘扫描、后台相册采集或自动读剪贴板权限。

1. 系统选择器返回 Android content URI 或 iOS 受限资源；原生层通过系统授权流式读取，不将 URI 当普通永久文件路径，不把任意路径暴露给 WebView。
2. 需要跨前台恢复保留文件时，采用受支持的授权保留或有界复制到应用私有 staging；不足空间明确失败。用户取消/上传确认后清理临时副本，不偷偷持久保存整个相册。
3. 显示文件名、大小、目标知识库与预计网络使用；蜂窝上传建议默认询问，阈值为此设备偏好。服务端仍执行配额、内容类型与哈希校验。
4. 照片压缩、去位置元数据作为明确采集选项；截图/扫描类图片优先可读性，图像派生须保留转换说明。HEIC/HEIF 等格式按服务端 capabilities 决定支持或显式转换，不能悄悄破坏文档内容。
5. 单请求上传期间建议保持前台；锁屏/强杀可能中断，界面显示“未确认接收”，恢复后先查 UploadSession，再有界重传。未持久保存的选中文件可能需要用户重新选择；不标“断点续传”或“后台已继续”。
6. 服务器确认接收后，手机可锁屏/离开，解析继续；手机与电脑看到同一文档任务。取消本机上传与取消服务器已提交解析分别操作，不能只隐藏进度。

后续确有大文件移动场景时，再建设分片会话、分片校验/合并、最终哈希、失效和查询恢复协议；需要后台传输时分别接入 OS 后台机制并实测，不能只装 Tauri 文件插件就宣称后台续传完成。

系统“分享至知识库”、iOS Share Extension 与 Android 分享 Intent 为下一增量；分享入口必须先展示内容、账号/知识库与提交确认。URL 首版作为链接笔记保存，不让服务器自动访问任意私网链接；网页抓取按既有出网约束独立审批。

### 15.9 PWA 安装、缓存与升级

PWA 运行在当前 HTTPS 服务来源。运营服务和自托管站点分别提供自己的应用入口、manifest 与同源 API；不把一个中央 PWA 的 Cookie 跨域转发给用户任意服务器。原生端服务切换继续走 EndpointResolver。

- manifest 声明稳定 id、start_url、scope、图标与 standalone 展示；提供按实际浏览器能力显示的安装说明，不强制假定都有安装提示事件。
- Service Worker 首版只缓存有版本号的公开应用壳和静态资产。鉴权 API、原文件、预览、模型配置、SSE、上传和导出绕过通用 CacheFirst，不把响应里的私有正文放共享 CacheStorage。
- 登录后的少量业务缓存与草稿仍由分区 DeviceStore 管理；离线显示可用边界。仅缓存静态壳并不意味着离线可登录、搜索、问答或读取全部知识库。
- 新版本 SW 下载成功后提示更新，先保存草稿并处理在途本机上传，再确认切换；新/旧前端都受 API 兼容窗口约束。资产缓存按版本清理，不删除其他账号尚未处理的草稿。
- 登录页、登出、切账号与版本升级都做主屏幕模式实测；浏览器与安装 PWA 会话是否共享按平台实际结果展示，不承诺一次网页登录自动登录所有入口。

### 15.10 原生能力与技术验证门禁

在 P2 后先做 Android/iOS 最小壳原型，核对锁定的 Tauri、插件及真实类型定义。原型只验证以下能力，不先开发推送、完整离线或大规模导航重构：

| 能力 | 必须证明 | 失败后的处理 |
|---|---|---|
| 认证 | HTTPS 登录、原生凭据存储、单飞刷新、跨服务不串凭据 | 保留失败证据，补窄原生实现，重新验收 |
| 流订阅 | 当前服务鉴权、消息序号恢复、前后台/断网后只订阅原任务 | 先用最终快照读取交付可用性，不冒称流恢复通过 |
| 文件/拍照 | 系统授权、URI 读取、空间限制、取消与重新选择 | 不降级为任意磁盘权限；限制为已验证的采集方式 |
| 设备存储 | 缓存隔离、草稿持久、退出清理、密钥丢失/恢复处置 | 原生加密缓存未验收前关闭正文持久缓存 |
| UI 与原生边界 | Android 返回键、iOS 返回/手势、键盘、安全区、外链受限 | 同一 Vue 调整移动布局，原生能力只授予可信本地前端 |

三个现有窄适配点继续复用；文件选择/生命周期只在有实际平台差异时加入小型原生方法，不建设通用“移动插件平台”。外部模型输出、文件 HTML、深链接目标不获取 invoke 权限，原生壳不加载任意远程页面替换可信 Vue。

### 15.11 可选通知与深链接

首版手机打开应用即可同步，无推送仍满足主线。后续加入“处理完成 / 回答完成”通知时，按设备单独授权和关闭，后台通知只提醒存在变更，不代替 SyncChange 或持久消息。

- 原生 iOS 通知接 APNs，Android 按分发渠道与实际服务可达性选通知提供方，不假定所有设备有同一推送基础设施；PWA 使用受支持的 Web Push。iOS/iPadOS 主屏幕 Web App 的推送支持从 16.4 起提供，需用户动作触发授权并按实际 OS 验证。[WebKit Web Push 说明](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)
- 拟新增 DeviceNotificationSubscription，绑定 device_session、service、provider、加密订阅目标、授权状态和失效时间。订阅标识不是认证 token；推送提供方凭据属于部署/平台配置，不进入个人同步。
- 持久任务完成后通过可重放发送记录触发通知，事件 ID 去重、有界重试；发送失败不影响任务终态或其他设备访问。撤销/退出后解绑订阅，已经发出的通知可能残留，因此默认文案仅“知识库有新结果”，不含笔记、问题、文件名或模型 Key。
- 点击通知只打开资源标识，登录后重新授权并读取当前版本；深链接参数不携带 access/refresh，不自动切服务器、不自动提交上传/付费请求。旧账号/已删除资源显示当前状态，不泄漏原内容。
- 推送被拒、延迟、重复或网络不可达时，应用回前台补拉仍得到同一结果；通知到达率另测，不作为数据可靠性承诺。

## 16. API 蓝图与错误契约

下表带“新增/改造”的接口仅是拟定契约，实施前对照现有路由。统一使用 `/api/v1/`，不为每个客户端复制一套后端。

| 方法与路径 | 状态 | 职责 |
|---|---|---|
| GET `/capabilities` | 新增，匿名低敏 | 服务身份与兼容范围 |
| POST `/auth/login`、`/auth/refresh`、`/auth/logout` | 既有，改造 | 设备会话与客户端认证模式 |
| GET `/auth/me`、`/auth/me/preferences` | 既有，扩展 | 个人身份与偏好版本 |
| GET `/auth/devices` | 新增 | 当前账号登录实例，不暴露 token；区分网页/PWA、桌面、Android、iOS |
| DELETE `/auth/devices/{session_id}` | 新增 | 撤销本人指定设备会话 |
| GET `/sync/bootstrap`、`/sync/changes` | 新增 | 快照与增量变更分页 |
| POST `/sync/ack` | 新增 | 当前设备已应用的通知游标 |
| GET/POST `/knowledge-bases` | 既有，扩展 | 个人空间知识库 |
| POST `/uploads`、POST `/uploads/{id}/complete` | 新增 | 上传 staging 与幂等确认；旧 file 接口兼容转发 |
| PATCH `/knowledge/{id}` | 既有资源路径，改造 | 条件写与 revision |
| GET `/knowledge/{id}/download`、`/preview` | 既有，扩展 | 授权、版本与受限缓存 |
| GET `/tasks/{id}` | 待统一/核对旧任务路由 | 根据真实空间范围返回状态 |
| POST `/sessions/{id}/generations` | 新增 | 幂等提交生成任务 |
| GET `/generations/{id}/events` | 新增 | 授权订阅与 cursor 恢复 |
| POST `/generations/{id}/cancel` | 新增 | 显式耐久取消 |
| `/sessions/continue-stream/{id}` | 既有，兼容保留 | 逐步转入同一恢复服务 |
| `/models`、`/models/{id}/credentials`、`/thinking` | 既有，扩展 | 个人模型、密钥状态与条件更新 |
| POST `/account/exports`、DELETE `/account/data` | 新增 | 个人数据导出与有确认的删除流程 |
| PUT/DELETE `/auth/devices/current/notification-subscription` | 可选新增，非首版依赖 | 当前设备通知订阅/解绑，独立授权；不返回其他设备订阅目标 |

错误码至少区分：401 `session_expired/session_revoked`、403 `action_forbidden`、404 `resource_not_found`、409 `revision_conflict/idempotency_mismatch`、410 `sync_cursor_expired`、412 `precondition_failed`、413 `upload_too_large`、429 `quota_exceeded`、503 `dependency_unavailable`。

保留现有响应封装，扩展结构化 code 与 request_id；字段验证错误不含凭据，浏览器显示可理解的信息。只对可安全重试的请求重试；POST 需要幂等身份，不把网络失败都自动重发。

建议创建生成请求（设计样例）：

```json
{
  "client_message_id": "message-request-demo",
  "expected_session_revision": 12,
  "text": "请根据我的知识库解释这个概念",
  "knowledge_base_ids": ["kb-demo"],
  "model_config_id": "model-demo"
}
```

幂等记录绑定账号、空间、动作、资源和请求哈希，不仅是任意 `X-Request-ID`；保留时间应覆盖客户端重试窗口，过期后不盲目重新执行有费用操作。

## 17. 服务端部署与数据库演进

### 17.1 首版生产目标

单机或托管实例上的 PostgreSQL + 持久文件目录 + Django API/流进程 + worker + 保留的 Neo4j；TLS 入口单独暴露，数据库、图谱管理端口不向公网开放。

可选 Langfuse 默认不作为启动依赖；内容采集与账号桥不会因从本地迁到服务器而自动启用。个人用户不能获得全局 Langfuse 管理会话。

### 17.2 SQLite 到 PG 的阶段门禁

受控早期试用可以继续单机 SQLite，但必须限制后台写并发并保留锁/取消/恢复测试。SQLite 只支持一个同时写入者，不能把文件放共享盘解决扩容。[SQLite 适用场景](https://www.sqlite.org/whentouse.html)

推荐发布前完成 PG 检索适配：

1. 清点 SQLite 专用 SQL、向量扩展、迁移和分块写入路径。
2. 在隔离 PG 实例跑 schema、检索 oracle 与任务合约，修复真实差异。
3. 为导入提供 dry-run、checkpoint、逐表行数、归属、哈希与抽样核验。
4. 停写窗口内停止领取任务，处理在途生成并显示维护提示，生成一致备份。
5. 导入并只读验收，再切换客户端服务；确认成功后开放写入。
6. 开放 PG 新写后，不允许直接换回旧 SQLite 快照；需要恢复兼容 PG 或经过验证的增量回放。

### 17.3 部署启动契约

当前 `APP_MODE=api` 与 `worker` 已有门控基础；检查所有任务派发、恢复与管理命令，不让 API 隐式启动解析进程。新增聊天生成任务后再登记 chat worker 入口，旧命令不假定支持新队列。

生产入口配置进程数、连接池、生成和解析并发、上传限制、模型超时、日志与可信代理；每项有范围与生效时机。部署与页面配置分层，密钥不写有效配置输出。

上线按 Django 部署检查逐项验证 TLS、Hosts、DEBUG、cookie、静态资源与日志；不能为了桌面或手机跨来源连接关闭全部来源校验；原生来源按实机与可信配置白名单验证，PWA 保持同源，来源字符串本身不作为用户授权凭据。[Django 部署检查表](https://docs.djangoproject.com/en/5.2/howto/deployment/checklist/)

## 18. 数据保护、隐私与运营访问

- HTTPS 保护传输，凭据加密保护静态存储；服务器执行解析/检索/模型调用时可接触明文，因此首版不宣称端到端加密或运营方绝不可读。
- 清楚列出第三方模型会接收哪些内容：问题、必要检索片段、用户选中的图片等；不默认传整个知识库。
- 用户导入文件前看到上传目的；诊断、遥测、正文采集分别有明确开关，不以“同步”为名默认采集本机目录。
- 普通运营排障只用低敏指标；访问用户正文要求有审计的明确操作与授权流程，不以 system_admin 全局身份进行日常检索。
- 密钥分为 Django 签名、用户凭据加密、备份加密、安装包更新签名，各自独立管理与轮换。
- 退出、换账号、设备撤销清理受保护缓存；公共静态资源可以共享缓存，用户数据响应采用私有缓存策略。
- 数据导出包含原文、笔记、会话、引用与非敏感配置及版本清单，默认不含模型 Key、登录 token、平台密钥。
- 账号删除具备再认证、确认、任务停止、数据 tombstone、清理进度与失败重试；备份中的历史数据按明确保留期自然淘汰，不宣称即时从所有备份消失。

## 19. 备份、恢复与“同步不是备份”

跨设备同时看到删除只说明同步正确，不能代替历史恢复。

建议初期目标：**RPO ≤1 小时、RTO ≤4 小时**，这是待演练目标，不是已经达到的保证；磁盘损坏前未完成异地备份的内容仍有风险。数据量、成本与保留周期需要发布前确认。

### 19.1 备份对象

业务数据库、不可变原文与必要产物清单、人工 Wiki/图谱修订事实、各类解密密钥与配置版本。Neo4j 机器投影可重建；人工修改不能只依赖重提取。

### 19.2 一致性备份策略

- 采用每日完整 + 小时级增量/PG 恢复日志与文件增量，副本写到独立故障域。
- 文件确认 ready 前已持久可读；备份记录数据库时间点 T 与该时间点引用对象的清单、哈希、备份完成状态。
- 恢复点只能在所有被引用对象和必要密钥均可取回后标 verified；不能只备份数据库却遗漏当天新上传文件。
- 文件不可变版本使备份可在数据库快照后补齐引用；物理清理与备份保留协调，避免对象被先删。
- 备份失败、对象缺失、日志积压和最新 verified 恢复点超时均告警。

### 19.3 恢复演练

在隔离环境还原 DB、文件与密钥，核对归属、文件哈希、人工内容、会话与有效索引；撤销历史登录会话。恢复旧时间点会回退业务版本，因此恢复后递增 service recovery_epoch / sync epoch，拒绝旧游标，客户端重新建立缓存并保留草稿，不能继续比较回退前的 revision。

彻底删除与账号删除使用独立、最小化的删除账本（空间/实体 ID、删除版本、时间，不含正文），存放在不随业务旧快照一起回退的受保护持久位置，并进入异地备份。最终删除完成状态必须等待账本耐久确认；普通软删除可以先对在线访问立即生效并显示后续清理状态。恢复开放服务前应用最新可取得的删除账本，重建 tombstone 和拒绝访问规则，防止旧备份复活已完成删除的数据。若账本缺失或落后，隔离相应资源并核查，不能直接开放旧快照。

恢复报告明确数据库/对象/删除账本的真实恢复点、RPO 内可能缺失的数据与耗时。service_id 保持服务身份，epoch 改变用于区分恢复世代，不用更换服务器地址绕过缓存失效。

至少按版本升级和定期计划演练。备份命令退出 0 不等于恢复成功。用户手动下载导出作为个人可控的第二条恢复路径。

## 22. 分阶段实施，按用户价值交付

### P0：冻结边界与基线

- 完整检查路由、依赖、用户/空间数据归属和原有修改，保存受影响文件哈希。
- 建立两用户三设备（电脑、Android、iPhone）、两个知识库和固定模型替身的隔离验收夹具；手机浏览器/PWA 与原生壳分栏记录。
- 明确服务运营/自托管默认、系统最低版本、图谱退化政策与数据保留期。
- 退出条件：有当前失败清单、兼容范围、数据迁移清单，未删旧功能。

### P1：同一服务器上的个人跨设备使用

- 明确个人空间 owner，调整个人/平台设置入口；统一前端地址和业务读取。
- 网页与手机响应式页面在线共享服务器数据，交付移动导航/键盘/引用返回；PWA 先建立可安装入口与公开静态壳，保留条件刷新与清楚的保存状态。
- 退出条件：A 上传/编辑后，B 重开页面能读取；不同账号所有资源互不可见。
- 回退：保留新增兼容字段，旧个人读取入口仍可访问同一服务器数据；不回退授权修复。

### P2：设备会话与凭据治理

- DeviceSession、原子轮换、token 摘要、网页/PWA cookie/CSRF 与桌面/手机原生认证接口契约；双手机平台原型验证凭据存储，不从桌面插件推断。
- 退出条件：单设备撤销、改密全撤销、刷新并发、响应丢失、跨标签页和跨服务器不串登录通过。
- 回退：采用明确短期兼容窗口；不能把新 token 发给只认识明文旧协议的服务。

### P3：条件写入与轻量变更同步

- resource revision、幂等记录、SyncChange、事务内 seq、bootstrap、分页、过期重建和 tombstone；移动前台恢复单飞、PWA 草稿与 SW 更新不丢输入。
- 退出条件：两设备并发编辑不丢输入；事务反向提交不漏变更；重复/乱序/崩溃和游标过期正确。
- 回退：停止增量通道后客户端可全量读取；保留未提交草稿与版本字段，不回退成无条件覆盖。

### P4：文档/生成任务耐久化

- staging、DocumentRevision、完整发布条件、任务范围，生成提交与订阅分离，取消/断线恢复。
- 退出条件：A 关机后服务器继续任务，B 接续同一消息；失主与删除不产生旧版本发布。
- 回退：协议版本隔离，停止领取新任务并 drain；保留旧有效版本，费用不确定的生成显式 interrupted。

### P5：服务端 PG 与搜索门禁

- 实现 PG 搜索/任务合约、中文 oracle、文件存储边界及导入校验，先在隔离环境验收再迁数据。
- 退出条件：全文、向量、Rerank、Neo4j 归属与质量回归通过；恢复与迁移核对通过。
- 回退：开放新写前可撤销切换；开放新写后必须保留 PG 新数据，不盲目恢复旧 SQLite。

### P6A：桌面三平台客户端与体验

- Tauri 壳、设备凭据适配、最小原生能力、各平台构建、安装/升级与网络异常体验。
- 退出条件：三平台干净机器不装 Python/Node 也能登录、上传、问答、切设备与撤销。
- 回退：上一兼容客户端 + 可重建缓存，保留本机未上传草稿。

### P6B：Android/iOS 手机客户端

- 在 15.10 技术门禁通过后，复用 Vue 交付手机 Tauri 壳、OS 凭据/私有缓存、系统选文件/拍照、上传确认、前后台/网络恢复。
- 退出条件：Android 与 iPhone 真机在同一账号下完成手机上传→电脑问答、电脑生成→手机接续；权限拒绝、锁屏/杀进程、换网、改密/撤销、安装升级与存储异常均有真实证据。
- 先取得签名测试包、TestFlight/选定 Android 测试渠道证据，再单独确认正式分发；PWA 通过不替代原生包验收。推送和分享接收不阻断基础手机发布，单独增量验收。
- 回退：保留上一兼容包与网页/PWA 入口，关闭未通过的可选原生能力；保留云端事实与未上传草稿，不要求服务端数据库倒退。

### P7：备份、发布与实际运行验证

- 导出/删除、异地备份与恢复、日志脱敏、试用容量、关键指标与发布检查。
- 退出条件：电脑/Android/iPhone 三设备端到端、故障恢复和各发布渠道签名/升级门禁有真实证据；移动网页/PWA、桌面、手机原生分开报告，线上目标按实测确定。
- 回退：停止新协议入口、保留用户数据，使用兼容发布或前向修复，记录恢复点与影响。

依赖：P0 → P1 → P2 → P3；P3 → P4 → P5；P1 交付移动网页/PWA 起步，P3 补移动同步/恢复；P2 后可做 P6A/P6B 壳与关键原生能力原型，P4/P5 稳定后按发布批次完成桌面三平台与 Android/iOS 验收；本方案完整交付需 P5/P6A/P6B → P7。每阶段可独立评审，不并发改认证、数据迁移和客户端发布协议。

### 23.2 起步性能目标，不是当前承诺

- 条件：独立测试环境；20 个个人测试账号，每账号 2 台模拟设备；10 路受控生成 + 5 个解析任务为初始组合。
- 活跃前台跨设备元数据刷新 P95 ≤5 秒；冷启动元数据读取 P95 ≤2 秒，原文件下载另测。手机另测前台恢复（正常有效游标，不含重新登录/全量重建）元数据可见 P95 ≤3 秒；网络条件、机型与缓存状态写入报告，不套用到后台冻结时段。
- 普通短 API P95 ≤300ms；输入规模、硬件、并发、索引数量与测量方法写入报告。
- 流事件服务端持久确认到客户端可见附加延迟 P95 ≤500ms；模型 TTFT 不计入该网络/应用目标。
- 文件构造多档大小，包含长 PDF、中文、图片、重复文件与两用户相同文件；超限返回明确状态。
- 验证期间任务积压在限定输入速率下能回落，线程/连接/内存有界；先测试稳态再测试恢复。
- SQLite 试用与 PG 生产目标分别报告，不把同一数据集某次通过外推成所有规模可用。
- 后续容量根据真实账号数、活跃设备、生成并发、文档量与上游配额扩展，不重新默认“个人产品只有一个用户”。

### 23.3 测试命令纪律

文档阶段只验证链接、JSON 样例、代码围栏与差异。实施阶段按 AGENTS.md：后端变更执行 `python manage.py check` 和相关 Django 测试，前端执行 `npm run test:unit`；改构建/依赖时再构建。完整套件仅在明确要求后运行。

新增测试模块建议分别为 devices、sync、personal_space、generation_recovery、PG_search_contract；需先创建后列入命令，不使用不存在的测试名冒充执行证据。真实浏览器/PWA、PG/Neo4j、桌面安装包、Android/iOS 真机、外部模型与替身测试分栏报告；手机断网、后台、系统杀进程和权限验证不能只由浏览器 mock 代替。

## 24. 数据迁移与旧功能处理

1. 盘点 User → Tenant → TenantMember 与所有业务对象，生成歧义报告；不以 user.tenant 自动认领多人空间。
2. 对明确个人空间回填 owner 与版本；多人 legacy 空间保持原授权，迁移到个人空间需用户选择与对象复制/移动记录。
3. 导入 media 前核验每条 file_path/storage_path 的存在、哈希、空间归属、引用与重复；孤儿或测试产物进入报告，不自动删除或上传。
4. 迁移凭据保留现有解密密钥与原数据库，解密失败停止该项；不重新生成密钥覆盖旧值。
5. User.preferences 按账号同步，设备路径等排除；原 localStorage 中敏感 token 按新认证策略迁移并清理。
6. 现有会话保留 UUID、请求关联与引用；未完成生成按可验证状态恢复，不能盲目重放付费请求。
7. 旧客户端有明确兼容窗口和停止支持通知；个人产品入口变化不等于直接删除旧路由、成员功能或本地启动器。
8. 所有破坏性迁移、删除、发布和实际服务切换单独确认；先用副本证明行数、哈希、权限和用户体验。

## 25. 决策日志与待确认项

待确认但不阻止先实现 P1：

- 默认服务是否由项目方运营；自托管地址入口是否首版展示。
- 预计个人账号总数、每人设备数、活跃生成、文档字节数与服务器预算。
- 是否允许缓存原文、是否需要敏感文件仅本地、不上传第三方模型的模式。
- 图谱故障是否允许普通检索继续；人工图谱编辑如何保留。
- 备份与回收站保留期、设备会话期限、密码找回/邮件服务政策。
- 桌面三平台与 Android/iOS 最低 OS/CPU、Linux 发行版、签名账号、更新/手机商店渠道；自托管 PWA 域名与安装身份。
- 手机是否需要系统分享接收、敏感正文离线缓存、推送和后台大文件续传；这些增强不阻断基础跨设备使用。

这些是产品选择，不用未确认答案推断用户只要本地版、只要团队版或必须千人集群。
